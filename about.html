About this demo

Harbor Watch MSSP is a fictional managed security provider. Every alert, host, user and address here is synthetic (documentation IP ranges, corp.example names).

What you are looking at: a replay of recorded run live-20261028 (claude-sonnet-5-5, recorded 2026-10-28): the agent triaged each alert once with the real model API, and replaying the recording costs $0 and makes no model call. The replay writes the audit trail; a live run writes it as it goes.

Dates and times: the recorded date is the one in the recording id. Times in the audit trails and trust reports (ending in Z) are UTC, so they can fall on the next day.

The agent can only read. Its recommended actions wait for a person, and the two approvals in this demo are dry runs recorded as "scripted demo approval". Threat intel is post-triage enrichment (synthetic provider answers); the verdict did not use it.

Reproduce it

From a clone: install from the lock files, then asa demo (replay, intel, two scripted approvals, evidence check, trust reports, this console). Check any trail with asa audit verify out/runs/<run>/<alert>.

Honest limits

  • Synthetic data and one recorded run (n = 30): the numbers describe this set, not your environment.
  • The evidence checker proves a quote exists in the cited event, not that the reasoning is right.
  • Planted instructions are a known set; text that does not look like an instruction is not flagged.
  • Threat-intel decisions come from synthetic provider answers, after triage; the verdict did not use them.
  • The console replays a run; it does not run the agent.
  • Approvals are dry runs: nothing is executed anywhere. Approver names are self-declared.
  • The audit trail is tamper-evident, not tamper-proof: a hash chain shows an edit, it does not stop someone rewriting the whole chain. The head hash of the demo run is written in the README so git history anchors it.
